## 0. 方向结论

- 第一阶段：规则信号引擎 + H5 前端跑通，能持续产出信号卡。
- **第二阶段转向**：把「信号 → 执行 → 持仓风控 → 平仓 → 复盘盈亏」**功能闭环**做完整，用**少量真实资金**实盘跑一段时间，以**实盘实际盈亏**作为评判策略优劣的最终指标。
- 执行方式已确认：**一键确认（半自动）小额实盘**；用户已有币安 U 本位**交易权限** API Key。
- ⚠️ 需打破「不自动下单」原则；API Key 安全红线见 §6。

## 1. 策略基线（现状核对 + 增强项）

### 1.1 现状框架核对（用户既定框架逐项比对）

| 要素 | 现状 | 代码依据 |
|---|---|---|
| 趋势过滤 | ✅ 完整 | 0️⃣市场环境（BTC 4h EMA55 + 涨跌家数比）；1️⃣方向门：4h EMA55 + 1h EMA7/21 排列 + 4h MACD 零轴 + ADX≥25 三条件一致 |
| 动量确认 | ⚠️ 有，但苛刻 | 2️⃣扳机：15m 触发（A 回踩/B 突破/C RSI 穿越）+ **5m MACD 柱"恰好刚翻色"** 同向确认 |
| 成交量验证 | ⚠️ 有，但只否决 | 3️⃣量能一票否决（量比<1.2 且 OI<+1%）；A 级缩量/B 级放量分级；无正向加分 |
| 波动率出场 | ⚠️ 半套 | 止损 = ATR×带宽系数(1.0/1.5/2.0) + 三段式（初始→保本1.5ATR→EMA21跟踪3ATR→1h 破位离场）；**出场是建议不自动执行**，无波动率通道出场 |
| 大/小周期框架 | ✅ 符合 | `TIMEFRAMES = {direction:4h, confirm:1h, entry:15m, micro:5m}`，4h/1h 定方向，15m/5m 找入场 |

### 1.2 薄弱点（数据 + 代码依据）

1. **动量确认卡死机会**：5m「刚翻色」瞬时捕捉 + 双周期共振 → 实测 166 候选池中 **142 个（82%）** 卡在「扳机未触发」，信号长期为 0，实盘无机会。
2. **出场是半自动**：止损三段式与出场预警已计算、已建议，但**未接入执行**（N1 补）。
3. **量能只否决不加分**：无量价配合的正向确认。
4. **只有一条入场路径**：产品设计为短线(15m/5m)+波段(1h/4h) 混合，**波段周期入场未实现**。
5. **仓位管理单一**：固定风险 2%，无波动率目标仓位（vol targeting）。

## 2. 闭环定义（要补完的链路）

```
信号引擎(已有) → 执行层(新) → 持仓+风控(新) → 平仓(新) → 复盘盈亏(新)
```

可复用资产：SignalCard 已含 `market_price/market_pct(70%)/limit_price/limit_pct(30%)/stop_loss/target/risk_reward`；
`position/manager.py` 已有止损三段式状态机；`signal/monitor.py` 已有活跃信号实时跟踪（判止损/过期）。

## 3. 模块设计（新增/扩展）

- **账户层**（新）：币安 U 本位交易 API；Key 存 `data/settings.json`（`BINANCE_API_KEY/SECRET`），不进库、不进前端、日志脱敏；仅开交易权限。
- **执行层**（新）：按信号卡执行计划下单（市价 70% + 限价 30%；第一版可仅市价）；**幂等防重**（信号 id）；最小下单量/精度处理；对账。
- **持仓风控层**（扩展）：止损三段式自动执行；加仓单 45min TTL 撤单；**单日亏损熔断**；单日开仓上限；相关性检查。
- **复盘层**（扩展）：真实成交 → 累计盈亏/胜率/盈亏比/最大回撤/分层盈亏（实盘核心指标）。

## 4. 执行模式（已确认）

| 模式 | 行为 | 状态 |
|---|---|---|
| ① 纸面模拟 | 虚拟订单零资金 | 保留（调试用） |
| ② **一键确认（半自动）** | 信号卡「执行」按钮 → 确认后真实下单（小额），止损/止盈自动跟踪 | **本次目标** |
| ③ 全自动 | 信号自动下单无人值守 | 最后，视验证再定 |

## 6. 风险与安全（红线）

- API Key 只开**交易**权限、不开提现；本地存储，日志/前端/对话绝不出现 Secret。
- 初始资金最小可交易额度；单笔风险 2% 沿用。
- 熔断：单日亏损阈值 + 每日开仓上限，达标自动停开。
- 全自动（③）必须等 ② 验证充分后再评估。
